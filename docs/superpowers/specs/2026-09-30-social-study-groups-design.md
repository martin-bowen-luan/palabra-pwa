## 1. 目标与范围

几位朋友在私人小组中看到彼此真实练习量、每日目标完成情况和一句话留言，可以发送“提醒学习”或“加油”。不要求邮箱或手机号；断网不影响背词，重新联网并打开应用后补传。

用户已选择：多人小组、自动打卡、每日一句话、昵称与设备身份、恢复码、应用内轻提醒，以及 Supabase 云端服务。保留 GitHub Pages 前端、IndexedDB 本地词库和学习进度。

本次设计不包含完整学习进度云同步、公开排行榜、聊天、系统推送、附件、付费功能或小学词表导入。AI 密钥、分析缓存、答题内容和 Wordle 记录不上传。

以下为首版建议默认值，随本文件一并确认：

- 每个身份同时加入一个私人小组，每组最多 10 人，包含组主。
- 每个身份同时绑定一个有效设备登录；身份恢复会替换旧绑定，不支持多设备同时打卡。
- 组名 2–30 字，昵称 1–20 字，留言最多 100 字，均按 Unicode 字符计数，只渲染文本。
- 小组统一按 `Asia/Shanghai` 划分日期，界面标注北京时间；本机原有每日计划仍按本机日期，不改变背词调度。
- 邀请码 7 天有效，可以提前撤销；每位发送者对同一成员的每种提醒每天各一次。
- 显示最近 30 天汇总及留言；提醒保留 30 天，后台定期清理过期数据。

## 3. 技术选择

推荐 Supabase Auth + Postgres + 受限数据库函数：复用托管身份与行级权限，事务处理入组容量、身份恢复、汇总更新和提醒频率。前端直接访问用户授权的接口，不自建常驻服务器。

备选一是 Cloudflare Workers + D1，需要另行实现身份、令牌及权限；备选二是只分享打卡图片，无法自动同步和收取提醒。用户已选择 Supabase，因此首版不并行支持多个后端。

不使用 Realtime 长连接；打开小组、应用回到前台和手动刷新时读取数据。小组页面在前台时最多每 60 秒更新一次，离开或离线即停止。

## 4. 身份与恢复码

仅在用户主动进入小组并同意共享说明后创建匿名 Auth 身份；普通背词不创建云端账号。首次流程为昵称、隐私说明、保存恢复码、创建或加入小组。

Supabase 匿名账号在清除浏览器数据后不能原样找回，所以使用独立稳定的 `profile_id`，通过私有绑定表关联当前 `auth.uid()`。昵称不是身份凭据，允许重名并用短成员标识区分。

恢复码采用浏览器密码学随机源生成的 256 位秘密，按组排版以便复制。服务端只保存 SHA-256 摘要。恢复码等同身份控制权，必须提示妥善保存；默认不永久保存明文，只在生成流程展示，之后可重新生成而不是查询原码。

恢复时新设备先完成匿名认证，再通过 HTTPS 请求体提交恢复码。服务端在事务中验证、绑定新 Auth UID、增加设备代次、撤销旧绑定并轮换恢复码。所有权限实时检查绑定，不能只依赖未过期 JWT；旧设备立即失去远端读写权，本地背词仍可用。

新恢复码由客户端预先生成，随幂等操作编号提交；确认响应前保存在待完成状态。响应丢失时可由相同新 UID 和操作编号查询是否已提交，不能要求再次消费旧码。恢复成功且用户确认保存新码后清除待完成明文。关闭页面丢失新码但登录尚在时，可主动轮换；不得提供免验证找回。

匿名身份尚未建立资料时可以恢复；已创建另一资料的设备不自动合并两个身份，应先明确退出当前小组身份。退出或清除本地凭据前提示保存恢复码。

恢复仅恢复昵称、小组资格及尚在保留期内的汇总，不下载完整学习进度。旧设备未上传的数据不能承诺找回。

## 5. 小组、留言和提醒

组主创建小组后获得邀请代码；代码使用至少 128 位随机值，服务端只存摘要。首版使用复制与粘贴代码，不将凭据放入页面 URL。加入前仅返回必要的组名和人数预览；成为成员后才可读成员数据。过期、撤销、无效代码统一明确拒绝，组满不创建半成功成员记录。

组主可改组名、重置邀请码、移除成员、转交组主或解散小组。普通成员可离开。组主必须先转交或解散，不能留下无组主小组。离开、移除和解散即时撤销访问权，操作需要确认；新加入的成员只查看自己加入后的小组日期数据，不获得更早历史。

每日一句话为每人每天一条，可修改或清空，单独点“发布”。离线允许保存草稿，但不自动对外发布未经确认的草稿；已确认发布的操作可以排队补传，并标明“待同步”。消息使用文本渲染，不解析 HTML、外链预览或 Markdown。

提醒只发给同组其他成员，不允许提醒自己。接收人可关闭接收；发送端显示相应状态。用户下次打开应用时看到未读提醒，可标记已读。服务端使用唯一约束限制每天每类一次，同时校验当前成员资格和接收偏好。

提醒必须在线发送，不在离线时积压过时的催促；界面显示“联网后可提醒”。不自动发送，不用误导性提示把“请求中”当作“已送达”。

## 6. 打卡统计口径

云端只接收每日、分语言的数字汇总、目标快照、日期、时区、最后练习与同步时间及主动发布的留言，不接收词条 ID、输入答案或完整会话。

在本地新增按日期、语言、词条去重的打卡台账，从加入后的实际持久化学习操作生成。旧历史不追溯上传；首次加入页面明确“从加入后的练习开始共享”。不把现有完成会话的简单相加直接当作新台账，避免重复练习和半组记录误算。

- 英语：达到本次学习最后一关，或用户明确跳过该单位时，计入一次已练习；重做和多关不重复计数。按任务最初分配区分新学与复习。手动标熟练但未练习，不计为新学完成。
- 西语：沿用每日词形练习的持久化事件；首次实际提交或跳过计一次，之后同日复测仅更新结果。新词形/复习分类保留第一次分类。单纯标熟练不计实际练习。
- 两种语言均额外记录“跳过待复习”数量；跳过可计已练习，不宣称已经掌握。曾跳过但同日随后无辅助通过，可更新最终状态。
- 英语目标完成率 = 当日已练习的新词数 / 当日新词目标；复习单列。西语目标完成率 = 当日新词形与复习总数 / 当日总量目标。进度条最高 100%，实际数量不截断。
- 两种语言独立显示，不将两个不同分母合并成一个完成率。不使用“已掌握”替代“已练习”。

小组日目标取北京时间当日第一次计入台账时的设置快照；当天修改设置不会追溯改变小组目标，次日采用新值。对本机日期与小组日期不同的用户，提示小组统计按北京时间汇总，因此可能与本机首页不同。

同一北京时间日期重复出现的词只按首次类别计一次；同一天新学后又到期复习不会同时算进两列。英语尚未结束的单位不虚增完成量，但已经结束的单位不必等整组完成才同步。

成员卡片显示最后成功同步时间。没有当日汇总时显示“今日尚未同步”，不能显示为“没有学习”。数据来自客户端实际操作，但首版不防篡改客户端或设备时钟，不作为排名或奖励依据。

### 换设备当天的明确限制

因为不上传逐词数据，服务端不能准确合并两个设备当天的去重词数。首版采用保守策略：保留恢复前已接收汇总，新设备分别上传自身快照；当天新学与复习各取新旧快照的较大值，不相加，目标快照保持不变。跳过数量取有效快照的较大值并限制在总量以内。卡片标注“今天更换设备，统计为保守汇总”。

这会少计某些跨设备新增练习，但不会把恢复前的数据清零或因重复补传翻倍。次日起使用当前设备正常汇总。恢复码不是跨设备进度同步，界面必须在恢复前说明此限制。

## 7. 离线、幂等与失败处理

本地学习保存事务同时更新打卡台账与待上传快照，复用当前 IndexedDB 会话版本校验。没有入组时不产生云端待传记录。网络失败不回滚已经保存的学习，也不阻塞下一题。

待上传项包含成员资格代次、设备代次、日期、语言和递增版本；每个键只保留最新快照。云端以替换快照而不是加法累积接收，重复版本返回相同结果，旧版本不能覆盖新版本。留言也有独立版本，清空留言是明确的删除内容操作。

打开应用、回到前台、恢复联网以及成功学习保存后合并触发同步。多个标签页通过浏览器锁或有过期时间的 IDB 租约只运行一个同步器，服务端幂等仍是最后保障。

网络和暂时服务错误采用带抖动的有限退避：同轮最多三次，之后等待下次前台/联网/手动重试。权限失效、被移除、设备已替换等永久错误停止上传并提示，不持续重试。请求已成功但本地未确认时，重新发送同一版本即可。

离组、换组或恢复后，旧成员/设备代次的队列不能上传到新身份；保留本地学习但隔离或丢弃旧队列，明确提示未同步部分不会共享。只补传仍在 30 天保留窗口内、且发生于有效成员时期的记录，过期数据本地保留并告知不再补传。

应用关闭时不保证后台同步；不依赖移动浏览器 Background Sync。离线展示已下载的小组缓存，并标注时间，不能把缓存伪装成实时状态。小组缓存仅本机保存，退出身份时清除；服务器撤权无法收回对方已经看到的内容，隐私说明要讲清楚。

## 8. 数据与模块边界

建议本地 IndexedDB v6 → v7，新增小组连接状态、去重台账、同步队列及小组只读缓存。保留现有词库、课程、进度、会话、AI 配置与 Wordle 数据。Auth 会话由专门的存储适配器管理，退出时统一清理；不得散落在多个不一致的存储中。

建议云端实体：

| 实体 | 责任与访问边界 |
| --- | --- |
| profiles | 稳定身份、昵称、提醒偏好；仅本人和符合可见范围的同组成员可读 |
| private.device_bindings / recovery_credentials | 当前 UID 绑定、设备代次、恢复摘要；不向客户端开放表读取 |
| groups / memberships | 组主、有效成员、加入离开时间、资格代次；成员限定读取 |
| private.group_invites | 邀请摘要、失效时间、撤销状态；只通过窄接口验证 |
| daily_summaries / daily_notes | 分语言汇总与每日留言；自己及有权同组成员读取 |
| nudges | 类型、发送接收人、日期、已读状态；只允许发送者或接收者读，不公开全组 |
| private.operation_receipts / rate_limits | 幂等确认与服务端频率限制；不对客户端开放 |

表必须有必要的唯一约束、外键、数字范围约束与查询索引。成员容量、恢复轮换、组主交接和提醒限额在事务中完成。汇总、留言读取需同时校验读者和作者的有效组关系及可见日期；跨组猜 ID 必须失败。

小组代码放入独立 `src/groups/`，分开管理身份、统计投影、存储、同步、远端接口和 UI。英语现有 `AppState` 与 `SpanishProvider` 只在已确认的学习事务边界提供数据，不在展示组件里发上传请求。不因小组子系统失败让词库或学习启动失败。

## 9. 安全与防滥用

- 所有暴露的数据表启用 RLS；未登录和仅有 publishable key 的请求不能读取成员信息。匿名 Auth 属于 authenticated，不等于允许读所有数据。
- 复杂写入通过受限 RPC：不得信任客户端提交的成员 ID、组主身份或接收人关系；从 `auth.uid()` 和当前绑定推导操作人。
- `security definer` 函数固定空或受控 `search_path`、全限定对象名、最小授权，并显式进行身份和成员检查。撤销默认 PUBLIC 执行权，避免函数绕过 RLS 泄漏私有数据。
- 注册启用 Supabase 支持的验证码和认证限速。恢复/兑换邀请码每 UID 每小时最多 5 次失败，创建组每资料每天最多 3 次，普通变更接口每 UID 每分钟最多 30 次；身份相关还设置项目级异常阈值与管理员关闭开关。频率限制服务端执行，失败计数不能随业务回滚而丢失。
- 邀请和恢复失败不泄漏对应身份是否存在。凭据只进 HTTPS 请求体，不进 URL、日志、错误上报或 Service Worker 缓存；验证码须由使用者完成。
- Service Worker 不缓存 Auth、小组 API 或验证码请求。前端 XSS 仍可能读取本地会话，不能宣称浏览器身份绝对安全；继续安全文本渲染并限制外部脚本。
- Supabase 管理密钥不进入浏览器。上线前单独验证权限矩阵，不能用“在管理员控制台能读到数据”代替用户权限测试。
- 清空本机背词记录不删除小组身份或历史打卡台账，界面说明已共享历史仍保留到期；提供独立“删除我的云端小组资料”操作，经确认后删除本人汇总、留言、提醒和绑定。组主需先处理小组归属，离组则不影响本机学习。

## 10. 界面

保留练习纸、蓝色批注、深色模式与四项底部导航。今日页增加“小组”文字入口及未读提示，进入独立 `/groups` 页面，不占用学习过程。

未加入时显示共享说明、填写昵称、创建/加入、恢复身份。入组后按成员展示两种语言的每日数量、进度、留言、同步时间和轻提醒操作；自己可编辑今天的一句话。组主操作与恢复码管理放在次级菜单，不混入背词按钮。

按钮触控区域至少 44px；网络、缓存、空数据、未同步、接收关闭、权限失效各有明确文案。颜色不作为唯一状态提示。关闭小组功能只停止同步与展示，不影响学习。

## 11. 验收与发布前提

- 两个设备以不同昵称创建/加入同组，第三个身份和另一组无法读取该组数据。
- 不登录不能读取；旧设备被恢复流程替换后，即使 JWT 未到期也无法继续读取、写入或领取提醒。
- 并发争抢第十个名额仅一人成功；离组、移除、撤销邀请和组主交接没有越权窗口。
- 恢复码无效、轮换重放、两设备同时恢复、事务失败及响应丢失均覆盖；不泄漏秘密且可识别已提交操作。
- 英语四关、西语错误重做、跳过、提示、标熟练、半组退出、多标签页、跨北京时间午夜与本机时区不同时，计数符合本文件口径。
- 离线学习重启后仍存在；联网补传一次，多次请求不翻倍；旧版本和旧身份队列不污染新数据。恢复当日保守合并有提示，目标不被空设置覆盖。
- 每日一句话草稿不自动发布；同类提醒频率受数据库约束，关闭接收立即生效。
- IDB 升级及禁用小组后，原有词库、未完成学习、AI、音频和 Wordle 均保持；服务不可用时仍可完整离线背词。
- 自动测试包括真实本地 Postgres/Supabase RLS 与事务集成测试，不只模拟前端。运行全部测试、TypeScript 检查和生产构建，检查手机/桌面深浅色及 GitHub Pages 子路径。
- 云端实际连通、验证码、两设备离线补传和恢复需真实浏览器验证；未执行必须列为缺口。发布时再次读取现有云端结构，应用版本化迁移，准备仅关闭小组功能的回退开关，不以删除学习数据回退。

- [Database Functions](https://supabase.com/docs/guides/database/functions)：函数权限及 security definer 的安全注意事项。
